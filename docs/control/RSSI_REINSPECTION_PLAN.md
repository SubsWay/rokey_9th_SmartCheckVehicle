## 1. 이번에 구현할 동작

기준선과의 변화량을 비교하지 않는다. 자기 섹터의 측정된 칸에서 **검출 RSSI 산술평균 < −72 dBm 또는 미검출 비율이 기준 이상**이면 후보로 선정한다. 해당 섹터 로봇이 그 칸의 안전한 지점까지 이동하고, **칸 안에서 정지한 상태로 10~15초** 새 표본을 모은다. 새 측정이 정상이면 해제, 이상이 남으면 회피 대상으로 확정한다.

기존의 `측정 → Dock → 필요한 칸 재점검 → Dock → 설비 점검 → Dock` 작업 흐름과 `inspection_manager`의 작업 소유권을 재사용한다. 후보가 없으면 재점검 왕복을 건너뛴다. 다른 로봇에게 교차 재점검시키지 않는다.

**기준의 우선순위:** 이번 사용자 요청을 이 작업의 기준으로 삼는다. 현재 저장소의 `requirements.md`, `process_flow.md`, `interfaces.md`와 실행 코드는 여전히 **중앙값·30초**를 명시한다. 평균·10~15초가 이미 구현됐거나 기존 문서 전체에 합의·반영됐다고 기록하지 않는다. 구현 단계에서 이 변경과 영향 범위를 함께 문서화한다.

### 기본값과 판정 규칙

| 항목 | 구현할 규칙 |
| --- | --- |
| 칸 크기 | 기존 지도 격자 0.5×0.5 m 유지. 측정 경로 줄 간격과 구분 |
| 평균 | `μ = sum(검출된 유효 RSSI) / n_detected` |
| 미검출 비율 | `q = n_missed / (n_detected + n_missed)` |
| 음영 후보 | `μ < −72 dBm` — 정확히 −72는 평균 조건상 정상 |
| 미검출 후보 | `n_total > 0`이고 검출 0개 또는 `q >= miss_ratio_threshold` |
| 미검출 비율 기본값 | **기존 0.5 유지 제안**. 설정으로 관리하고 경계값 포함 여부를 고정 |
| 최소 표본 | 통합 DB의 `min_samples` 설정을 사용. 현재 seed 기본값 3. 전체 유효 표본 수 기준이며 검출/미검출 수는 별도로 보존 |
| 정지 측정 시간 | **기본 15초 제안**, 10~15초 범위에서 설정. 기존 DB의 30초 값은 이 기능 적용 전에 명시적으로 변경·검증 |
| 해제 | 새 측정이 유효하고 최소 표본을 충족하며, 검출값이 있고 `μ >= −72` 및 `q < 기준`을 모두 만족 |
| 남음 | 새 측정이 유효하고 최소 표본을 충족하며, 평균 또는 미검출 조건이 여전히 이상 |
| 판정 불가 | 표본 0개·표본 부족·위치 불확실·칸 이탈·정지 조건 미충족·측정 실패. 해제나 확정 이상으로 바꾸지 않음 |

표본이 전혀 안 온 것과, 스캐너가 계속 발행했으나 모두 `detected=false`인 것은 다르다. 전자는 측정 실패/판정 불가이고 후자는 충분한 표본이 있을 때 미검출 이상이다. 검출되지 않은 RSSI를 0 dBm이나 −100 dBm으로 평균에 넣지 않는다. 미측정 칸은 이번 재점검 후보에서 제외한다.

## 2. 현재 기준 브랜치에서 확인한 차이

| 연결 구간 | 현재 코드 | 이번 작업 |

| 후보/이력 DB | manager의 `REMAINS`와 DB의 `CONFIRMED`가 다름. bridge의 알림 저장만으로 후보 상태 전이가 완성되지 않음 | 후보 생성→재점검 작업→결론·정밀 측정·이상 이력의 연결을 하나의 저장 경로로 완결 |
| DB 참조 | manager는 `cell:ix,iy`, 웹 이력은 DB cell_id 문자열을 기대 | 내부 칸 좌표와 DB cell_id를 명시적으로 변환 |
| 회피 | `mask_cells()`가 DB의 음영·미검출 칸을 바로 사용 | 재점검 결과와 미처리 상태를 구분해 적용. 초기/재점검 중 빈 마스크 정책 유지 |

이 브랜치는 이미 `SCV_RUN_OWNER=ros`, `ros_bridge.py`, DB 칸 저장·작업 동기화가 있다. 이를 재사용한다. 이전 `feature/Integration_db`의 `c1bcfb9`·`3d66513`은 현재 기준 커밋의 조상이 아니다. 이전 구현 전체를 자동 병합하거나 이번 기반에 들어 있다고 가정하지 않는다.

### P1. 판정 정책·설정과 데이터 계약 통일

1. ROS에 의존하지 않는 공통 판정 함수를 두고 평균·미검출 비율·최소 표본·정확한 경계 조건을 고정한다. 후보 선정과 재점검 결과 판정이 같은 함수를 사용한다.
2. 현재 DB settings를 기준으로 임계값·최소 표본·측정 시간을 읽고, 회차 시작 시 스냅샷을 고정한다. 실행 중 설정 변경으로 같은 회차의 판정 기준이 바뀌지 않게 한다. file 시험도 같은 설정 구조를 사용한다.
3. IF-04 `PreciseMeasure`와 IF-11 `ExecuteTask`에 필요한 평균·표본 수·측정 유효성/실패 사유를 추가한다. 기존 중앙값·IQR·검출 수는 호환·진단용으로 유지하되 이번 판단에는 사용하지 않는다. 사람용 reason 문자열에서 수치를 복원하지 않는다.
4. 목표 칸·회차·작업 식별과 측정 시간 구간을 전달하는 최소 계약을 확정한다. 목표 칸 검증에 필요한 자료를 추측하지 않는다.

완료 기준: 평균/중앙값이 다르게 판단되는 데이터, −72 경계, 비율 0.5, 전부 미검출, 표본 없음/부족의 정책 시험 통과. 인터페이스를 바꾸면 관제 PC·로봇 PC의 `scv_msgs`와 의존 패키지를 함께 재빌드해야 한다.

### P2. DB에 재점검 근거를 보존할 수 있게 연결

1. 기존 `grid_stats / precise_measures / candidates / findings / tasks / robot_events / net_samples`를 재사용한다. 별도 작업 관리 시스템이나 기준선 테이블을 만들지 않는다.
2. 필요한 추가 필드만 비파괴 마이그레이션으로 넣는다: 원본의 detected, 칸의 검출/미검출 수, 정지 측정의 평균·전체/미검출 수·유효성 및 측정 구간 등. 기존 n·n_samples의 의미를 명시하고 독자별 해석을 통일한다.
3. 검출이 없을 때 평균·중앙값은 NULL로 보존할 수 있게 한다. 기존 정밀 측정의 중앙값 NOT NULL 제약과 화면 처리를 함께 확인한다. 과거 자료에 없던 미검출 수를 임의로 0으로 채우지 않는다.
4. TF 모드 태깅의 고정 run_id와 bridge의 현재 회차 재부여를 최소 범위에서 바로잡는다. 표본 시각·회차·로봇·작업·대상 AP를 유지하고, 재전송은 원래 키로 중복 제거한다. 원본 버퍼 전체 이식은 이번 단계의 전제가 아니다.
5. 정지 측정 원본을 재점검 작업에 연결할 수 있도록 기존 SURVEY_SEGMENT 전용 task 제약·트리거를 확인해 필요한 부분만 확장한다.

완료 기준: 별도 시험 PostgreSQL에서 기존 데이터 유지, 전부 미검출 저장, 회차/AP/지도 혼입 방지, 중복 저장 방지 확인. 운영 DB 초기화나 기존 데이터 삭제 없음.

### P3. 후보 생성과 같은 섹터 로봇 배정

1. 1차 칸 저장 성공을 확인한 후 같은 회차·지도·대상 AP의 평균/미검출 통계를 읽는다. DB 읽기 실패를 ‘후보 0개’로 취급하지 않는다.
2. 섹터 안의 도달 가능한 측정 칸만 선정한다. 기존 점유 지도·벽 여유 검사를 재사용한다. 중심이 안전하지 않은 칸을 방문했다고 가정하거나 이웃 칸의 측정으로 대신 해제하지 않는다.
3. 목표는 칸 중앙의 안전한 지점을 우선 사용한다. 안전한 목표가 없거나 경로가 막히면 접근 불가로 남기고 정상 해제하지 않는다.
4. 기존 `zone_by_robot`와 실제 섹터 설정으로 담당을 고정한다. 같은 회차·AP·칸의 내부/외부 후보는 하나로 합친다. 후보·작업 ID는 DB의 길이 제한과 회차 간 유일성을 만족시킨다.
5. 후보와 원래 측정 작업의 연결을 저장하고, 재점검 작업 생성 시 `OPEN → REINSPECTING`과 작업 FK를 맞춘다. 후보가 없으면 기존 건너뛰기를 유지한다.

완료 기준: robot4/Z1, robot3/Z2의 자기 섹터 배정, 경계·외부 좌표·다른 회차·중복 후보 차단, 5칸 초과 후보 유실 없음, DB 제약 통과.

### P4. 칸 안 정지 측정 구현

1. 기존 Nav2 목표 이동을 재사용한다. 경로 계획 성공을 실제 도착으로 취급하지 않는다.
2. 목표 도착 후 정지 명령과 최신 위치·위치 품질·실제 정지 상태를 확인한 뒤 측정 창을 연다. 정지 확인에는 기존에 얻을 수 있는 자세와 odom 정보를 사용하며 허용 오차는 설정·기록한다.
3. 실제 집계는 위치가 유효하고 목표 칸 안이며 측정 창 안에 발생한 새 표본만 사용한다. 이전 캐시, 늦게 온 과거 표본, 재전송 중복, 다른 로봇/회차 자료를 제외한다. 이동 중 자료를 정지 측정에 섞지 않는다.
4. 기본 15초 동안 검출/미검출을 모두 센다. 시간 제한은 단조 시계로 관리하고, 원본 ROS 측정 시각은 별도로 보존한다. 동시에 두 측정을 받아 서로의 표본을 덮지 않도록 한다.
5. 도중 이동·칸 이탈·위치 신선도 상실·취소·비상정지·저전압은 명확한 실패/판정 불가로 반환한다. 실패한 짧은 구간으로 정상 해제하지 않는다.

완료 기준: 가짜 위치·odom·RSSI·액션 서버에서 10/15초 창, 오래된 표본 제외, 칸 이탈, 무발행과 전부 미검출 구분, 취소 및 동시 요청 시험 통과. 실제 cmd_vel·Nav2 액션은 실물에 전송하지 않는다.

### P5. 해제·남음·회피와 저장 순서 완결

1. 정지 측정 결과만으로 재판정한다. 1차 이동 측정과 섞어 좋아진 값을 다시 낮추거나, 과거의 강한 값으로 현재 이상을 숨기지 않는다. 원본과 1차 통계는 이력으로 보존한다.
2. 기존 저장 계층에 재점검 결과 적용 경로를 두고 정밀 측정·칸 최종 값·후보 결론·finding을 트랜잭션으로 일치시킨다. bridge가 같은 후보 결론을 또 쓰지 않게 저장 책임을 고정한다.
3. `CLEARED`는 정상 해제, 남은 이상은 DB의 `CONFIRMED`와 회피 상태로 연결한다. UI 문구는 ‘남음’으로 표현할 수 있으나 서로 다른 코드가 누락되지 않게 한다.
4. DB 실패 시 완료/해제 알림과 다음 단계 전환을 보류하고 같은 결과를 멱등 재시도한다. 후보/결론 알림은 저장된 식별자로 내보내며, 현재 실행 중인 다른 작업을 잘못 연결하지 않는다.
5. 판정 불가는 `UNCONFIRMED`로 구분한다. 기본 재시도 1회를 계획하며, 여전히 불가하면 해당 칸을 통과시키는 설비 작업은 보류하고 회차를 partial로 기록한다. 무응답을 RF 미검출 확정으로 바꾸지 않는다.
6. 저장된 재점검 후 이상 칸으로 회피 마스크를 만들고, 설비 작업 전에 적용을 확인한다. Dock 보호 반경 예외는 기존 정책을 유지하되 제외된 이상 칸과 사유를 기록한다. 재점검하지 못한 칸을 재점검 확정 이상처럼 표시하지 않는다.
7. 기존 웹에서 평균·검출/미검출 수·재점검 전후·해제/남음/판정 불가가 같은 값으로 보이도록 필요한 응답·상세만 연결한다. 앞서 만든 UI 시안의 디자인 이식은 이번 범위에 넣지 않는다.

완료 기준: 해제 칸 마스크 제외, 남은 칸 포함, 저장 실패 시 해제/다음 단계 금지, 중복 결과 1건, 후보·정밀 측정·DB 칸·finding·웹 상세가 서로 일치.

## 2026-10-15 진행 기록 — 세 결함을 순차 수정

### 먼저 바로잡은 현행 설명

`manager_core.remeasure_targets(include_unmeasured=True)`에는 미측정 재방문 옵션이 있고, PLAN N-6에도 10/14 실제 미측정 칸 재방문 기록이 있다. 현재 manager 기본값은 `include_unmeasured=False`다. **옵션이 없다는 설명은 잘못이며, 별도 N-8 자동 채우기가 완성됐다는 뜻도 아니다.** 이 옵션을 다시 켜거나 N-8을 구현하지 않았다.

### 이번에 고친 범위

1. **미검출 원본 유실:** bridge는 도크 위 표본만 제외하고 `detected=false`도 저장한다. DB `net_samples`에 detected를 추가하고 미검출 RSSI는 NULL로 저장한다. 평균·히트맵에는 검출 수치만 사용한다. 표본 API는 detected, 작업별 통계는 검출/미검출 수를 반환하며 웹 표본 점은 미검출을 회색으로 표시한다. 기존 데이터는 검출값으로 유지하며, 과거에 버린 표본은 복원할 수 없다.
2. **잘못된 해제 및 수집 실패 혼동:** 1차/재점검은 공통 평균 판정을 사용한다. IF-04/IF-11로 검출/미검출/전체 수, 평균, 측정 시간과 유효성을 전달한다. 무표본·전체 3개 미만은 판정 불가, 충분한 전부 미검출은 미검출 이상이다. latched 과거/중복/다른 로봇/시간 창 밖 표본을 제외하고 중복 정밀측정 목표는 거절한다. reason 문자열에서 통계를 복원하지 않는다. 기본 15초, 허용 10~15초. mission_executor는 목표 칸·위치 표준편차·odom 정지·시작 위치 대비 이탈·배터리를 검사하고 실패 시 판정 불가로 종료한다. 1초 정지 확인 뒤 측정한다.
3. **저장 실패 뒤 성공 판정:** 저장 False/예외이면 해제·남음·작업 완료를 보류한다. 수집된 결과를 메모리에 두고 dispatch 주기에 저장 재시도하며, 성공 후 완료한다. File/DB 모두 전체 표본 3개 기준으로 confidence를 계산하고 평균·검출/미검출 수를 갱신한다. 재측정 후 예전 분산·최솟값·최댓값은 NULL로 비워 혼합하지 않는다. 회피 마스크는 이번 재점검에서 유효한 이상 결과가 저장된 칸에만 적용한다. 무표본으로 원래 자료를 덮지 않는다.

관련 보완: 후보를 기본 5칸으로 자르던 설정을 0(전체)으로 변경했다. 양수 제한을 명시하면 제한이 유지되며, 남은 미재점검 후보는 확정 회피로 취급하지 않는다. 표본 부족 칸과 진짜 미측정 칸은 별개다. 후보 정렬도 평균이 낮은 순으로 바꾸었다. 기존 중앙점은 유지했다.
