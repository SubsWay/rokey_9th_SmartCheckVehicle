## 오늘 한 일

- `scv_detection`의 기본 실행을 “원본 카메라 미리보기”로 변경함. `ros2 run scv_detection scv_detection_manager`만 실행하면 기본 `/robot4` 카메라를 구독하고 창을 표시하며, 요청 전에는 YOLO 추론·랙 검사·ROI 표시를 하지 않음.
- `enable_yolo`, `rack_enabled`를 실제 검사 실행 상태가 아니라 각 서비스의 사용 허용 설정으로 분리함. 기본값은 둘 다 true이고, 실제 모드는 `_inspection_mode = None / 'yolo' / 'rack'` 중 하나임.
- YOLO와 랙을 각각 `std_srvs/srv/Trigger` 서비스로 제어하도록 구성함. 두 기능은 동시에 검사하지 않으며 다른 검사로 전환하려면 현재 검사를 먼저 중지함.
- 기존 약 5초 후 자동 종료 방식에서 **첫 호출은 시작, 같은 서비스의 다음 호출은 중지**하는 토글 방식으로 변경함. 시작한 검사는 다음 중지 요청까지 유지하며, 카메라가 끊겨도 중지 요청은 처리됨.
- 서비스 응답은 검사 판정이 아닌 **시작·중지 제어 성공 여부**로 정의함. `success=true`와 `message`의 `started`/`stopped`로 상태 변경을 확인하고, 실제 검출과 랙 판정은 영상·로그에 표시하며 불량은 `inspect/result` 토픽으로 발행함.
- `weights`를 생략하면 ament 패키지 인덱스로 설치된 `share/scv_detection/models/best.pt`를 찾도록 변경함. 모델은 첫 YOLO 시작 요청 때만 로딩하고 이후 재사용함. 잘못된 모델 경로는 해당 요청만 실패시키며 기본 카메라 실행은 유지함.
- `detection_render.py`를 제거하고 매니저의 `annotate_yolo_result` 한 함수와 `YOLO_CLASS_STYLES`로 YOLO 표시를 통합함. 모델에서 실제로 검출된 여섯 클래스의 이름·신뢰도를 유지하고 ID별로 색상을 직접 지정함.

### 실행·서비스 명령

노드 실행은 한 터미널에서 유지하고 서비스는 다른 터미널에서 호출함.

```bash
ros2 run scv_detection scv_detection_manager
```

YOLO 시작·중지는 같은 명령을 사용함.

```bash
ros2 service call /robot4/detection_alert/inspect_yolo std_srvs/srv/Trigger "{}"
```

랙 검사 시작·중지도 같은 명령을 사용함.

```bash
ros2 service call /robot4/detection_alert/inspect_rack std_srvs/srv/Trigger "{}"
```

- 다른 검사가 켜져 있거나 모델 로딩·기준 변경 중이면 `success=false`, `busy: ...`로 거절함.
- 시작에는 최근 영상이 필요하며 `camera_timeout` 기본값은 2초임. 랙 시작에는 정상 기준도 필요함.
- `camera_timeout`은 시작 시 영상 유효성 확인용이지 검사 종료 타이머가 아님.
- 코드 수정은 실행 중인 프로세스에 자동 반영되지 않으므로 노드를 종료한 뒤 다시 실행해야 함.

### 추가 작업: 불량 검출 토픽 발행

- 기존 `scv_msgs/msg/InspectionResult`를 사용해 `/robot4/inspect/result`에 불량을 발행하도록 추가함. `scv_msgs` 메시지 정의와 `scv_bringup`은 변경하지 않음.
- YOLO의 `Abnormal_left`/`Abnormal_right`는 `kind=1`(소화기), `Exit_sign_off`는 `kind=3`(유도등)으로 첫 검출 프레임에서 바로 발행함.
- 랙 돌출은 기존 기본 3프레임 확인 직후 `kind=4`(랙)로 발행함. 실행 시 `rack_confirm_frames:=1`로 바꾸면 첫 돌출 프레임부터 발행할 수 있지만 오검출 억제 효과는 줄어듦.
- 모든 불량 메시지의 `verdict=4`는 ABNORMAL임. `detail`에는 모드·클래스·신뢰도·좌표 또는 랙 돌출 원인·목록을 JSON으로 담음.
- 불량이 보이는 처리 프레임마다 발행하며, 대기·중지·정상·미확인·검출 0건·추론 오류에는 발행하지 않음. 정상 복귀 해제 이벤트와 동일 물체 중복 제거는 현재 범위에 포함하지 않음.
- 입력 영상 시각과 robot_id를 넣되, 현재 Trigger에 없는 순찰·설비 ID는 기본값으로 유지함. 증거 사진은 메시지에 중복 첨부하지 않고 기존 compressed 영상 출력을 사용함.
- 발행 직전 검사 모드·요청 번호·종료 상태를 확인하고 상태 잠금 안에서 발행하여 중지한 검사의 늦은 불량 결과를 차단함.
- 불량 발행 회귀 시험을 포함한 **65개 테스트 통과**, 선택 패키지 symlink 빌드 성공을 확인함.
- 별도 ROS 도메인에서 합성 YOLO Results를 실제 서비스·영상 콜백에 넣고 소화기·유도등 불량 토픽을 수신함. 실제 `ros2 topic echo --once` 명령으로 JSON 원인 출력도 확인함.
- 합성 랙 JPEG에는 실제 OpenCV 비교·3프레임 확인을 적용해 랙 불량 발행을 확인함. 두 서비스의 중지 이후 새 불량 발행이 멈추는 것도 확인함. 이는 현장 검출 정확도 평가와 구분함.
- README와 architecture.md에 메시지 필드·발행 조건·명령·운영 적용 범위를 반영함.

불량 메시지 전체 확인:

```bash
ros2 topic echo /robot4/inspect/result scv_msgs/msg/InspectionResult
```

불량 원인만 확인:

```bash
ros2 topic echo /robot4/inspect/result scv_msgs/msg/InspectionResult --field detail --full-length
```

검사 서비스를 켠 뒤 불량이 검출되어야 메시지가 출력됨. 메시지가 없다는 사실을 정상 판정으로 해석하지 않음.

### 추가 작업: 검출 화면 클릭 Depth 로그

- 참고 파일 `/home/mu-09/to_students/day3/3_3_a_depth_checker.py`의 깊이 구독·픽셀 읽기·단위 변환을 현재 검출 창에 연결함. 도킹·언도킹·이동 코드는 가져오지 않았으며 참고 원본 파일은 수정하지 않음.
- 기본 `/robot4/oakd/stereo/image_raw`를 `sensor_msgs/msg/Image`로 구독함. RGB 추론 중에도 수신하도록 별도 콜백 그룹과 BEST_EFFORT QoS를 사용함.
- 화면을 왼쪽 클릭하면 표시된 RGB의 원본 픽셀로 좌표를 변환하고, 최근 30개 Depth 중 촬영 시각이 가장 가까운 프레임을 고름.
- `16UC1` 밀리미터는 미터로 변환하고 `32FC1`은 미터를 그대로 읽음. 기본 유효 범위는 참고 코드와 같은 `0.2 < m < 5.0`임.
- 클릭 위치에 노란 십자를 남기며 `Depth RGB=(320, 240): 1.420 m raw=1420 encoding=16UC1 dt=0.012 s` 형식으로 클릭당 한 번 로그를 출력함.
- 값이 0·NaN·무한대·범위 밖이거나 RGB/Depth가 없거나 오래됐거나 시각·크기·좌표계 조건이 맞지 않으면 거리 대신 원인 경고를 출력함. 해상도가 다른 사진을 임의 비례 변환해 같은 위치라고 가정하지 않음.
- 좌표 변환·깊이 단위 계산은 새 함수 모듈 `depth_checker.py`에 분리하고 ROS 수신·캐시·GUI 클릭 처리는 매니저에 유지함. `cv_bridge` ROS 의존성을 선언함.
- 실제 robot4의 읽기 전용 구독에서 RGB와 Depth가 640×480이고 같은 optical frame_id이며 Depth가 16UC1인 것을 확인함.
- 기존 65개와 새 깊이 시험 44개를 합한 **전체 109개 테스트 통과**, 패키지 symlink 빌드 성공을 확인함.
- 별도 ROS 도메인에서 합성 RGB·Depth를 실제 전송하고 클릭 콜백의 1.250m/2.500m 로그가 `/rosout`에 도착하는 것을 확인함. GUI 등록은 시험했지만 실제 창에서 물리적으로 클릭하는 동작과 실물 거리 정확도는 별도 사용자 확인 대상으로 남김.
- 이 기능은 한 픽셀의 카메라 Z축 깊이 수동 조회이며 지도 좌표·3D 직선 거리·설비의 돌출 길이 측정이 아님. 기존 불량 토픽에는 깊이를 추가하지 않음.

### 실행 환경 확인 결과

- 불량 토픽 추가 후 현재 실행 환경에서 토픽 확인이 잘 된다는 사용자 보고를 받음.

- 노드 실행 → 원하는 검사 서비스 시작 → `ros2 topic echo`로 불량 확인의 사용 절차와 발행 조건을 문서에 정리함.
- architecture.md의 마지막 부분은 발표 화면에 그대로 사용할 수 있도록 “운영 적용 전 검토 사항”과 “설계 요약”으로 정리함. 비공식적인 상사·예상 질문 표현은 제거하고 구현 범위와 보완 사항은 유지함.

## 시행착오

- 인자 없는 실행에서 `weights is required`로 종료되던 문제를 확인함. 경로 자동 선택과 지연 로딩을 적용해 기본 카메라 실행과 YOLO 모델 준비를 분리함.
- 일반 설치에서 symlink 설치로 전환한 뒤 기존 터미널의 PYTHONPATH에 새 빌드 경로가 없어 `PackageNotFoundError: scv-detection`이 발생함. 실행 파일은 찾았지만 Python 패키지 메타데이터를 찾지 못한 문제였고, 환경을 다시 source하거나 새 터미널을 열어 해결함.
- bashrc 자동 source는 새 터미널 시작 때 적용되므로 이미 열린 터미널의 환경을 자동으로 갱신하지 않는다는 점을 확인함.
- 기존 서비스는 약 5초 동안 검사하고 종료했으므로 지속 감시에 맞지 않았음. 결과를 기다리는 방식 대신 모드를 유지하고 시작·중지 결과만 응답하도록 변경함.
- 모델 로딩과 서비스 응답을 분리해 설명함. 서비스는 최종 판정을 기다리지 않지만 첫 YOLO 시작에는 모델 로딩 시간이 포함됨.
- 과거 5클래스 모델의 평가 수치와 현재 6클래스 모델을 혼동하지 않도록 정리함. 현재 기능 시험 통과를 실환경 정확도 통과로 표현하지 않음.

- `colcon build --symlink-install --packages-select scv_detection` 빌드 성공을 확인함.
- 별도 ROS 도메인의 합성 JPEG 입력으로 실제 서비스 통신을 시험함. 랙 검사가 6초 이상 유지되면서 정상·돌출 판정을 표시하고 재호출로 중지되는 것을 확인함.
- 실제 현재 `best.pt`를 CPU에서 로딩한 YOLO도 6초 이상 유지되고 재호출로 중지되며 카메라 출력이 계속되는 것을 확인함.
- 위 시험은 서비스 제어·통신·표시 경로 검증임. 로봇 실영상의 클래스별 precision/recall, 장시간 안정성, 실제 돌출 거리 정확도를 측정한 것은 아님.
- 두 사용자 일지는 작성자 이름에 따라 내용을 나누지 않고 파일 내용까지 동일하게 유지함.
- 사용자 실행 환경에서도 불량 토픽 확인이 잘 된다는 보고를 받아, 오늘 작업의 완료 범위를 서비스 제어·영상 표시·불량 이벤트 발행으로 정리함.
