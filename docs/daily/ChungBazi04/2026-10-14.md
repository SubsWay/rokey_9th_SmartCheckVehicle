## 오늘 한 일

- MSI의 현재 `scv_detection` 코드와 기존 기록을 대조하여 소화기 압력계, 비상구 점등, YOLO 랙 적재, ArUco, 방화셔터 기능의 실제 연결 상태를 정리함. 영상 수신·모델 추론·서비스·화면·ROS 발행은 `scv_detection_manager.py`에서 관리하고 설비별 계산은 별도 모듈을 호출하는 구조를 유지함.
- 현재 MSI의 `models/best.pt`를 직접 읽어 **5개 객체 클래스**를 확인함. 이전의 정상·좌우 비정상·비상구 on/off 상태 클래스 모델과 구분함. 오늘 일지 정리에서는 새 학습이나 추론을 실행하지 않음.
- 소화기를 먼저 검출하고 내부 압력계를 연결하는 흐름을 유지함. 전체 영상에서 압력계를 못 찾으면 같은 YOLO 모델로 소화기 영역을 다시 검사함.
- `extinguisher_pressure.py`의 압력 판독을 바늘 각도 비교가 아닌 **정상 색 영역 안의 노란 바늘색 존재 여부**로 구성함. 녹색·청록색 정상 눈금과 빨간 비정상 배경의 색 차이를 사용하며, 정상 영역 안의 연결된 바늘색 픽셀이 기본 3개 이상이면 정상 후보, 없으면 비정상 후보임. 압력계나 정상 영역 자체를 찾지 못한 경우는 미확인으로 구분함.
- 정상 복귀는 같은 압력계의 새 영상에서 **0.5초 이상·최소 3프레임** 연속 확인 후 확정하도록 보완함. 비정상 후보는 즉시 반영하며, 대상 누락·카메라 단절·추론 실패·검사 시작/중지 때 확인 이력을 초기화함. 시간 확인은 화질이나 지속적인 색 오판을 해결하는 기능과 구분함.
- `rack_loading.py`에서 YOLO의 `rack`·`box` 검출을 이용해 박스 소속 랙과 경계 초과를 판독함. 왼쪽·오른쪽·위·아래 초과 픽셀과 비율을 기록하고 같은 대상의 새 프레임 3장으로 상태를 확정함. 소속이 모호하거나 화면에서 잘린 대상, 박스가 없는 랙을 정상으로 단정하지 않음. 이 방식은 영상의 사각형 경계 비교이며 실제 앞뒤 돌출 거리를 측정하지 않음.
- `exit_sign.py`를 매니저의 YOLO 검사에 연결함. 검출된 표지의 밝기 중앙값·상위 밝기·녹색 비율·밝은 픽셀 비율·주변 대비로 점등/소등 후보를 만들고 0.5초·3프레임 연속 확인함. 정상/점등은 초록, 비정상/소등은 빨강, 미확인은 회색으로 표시함. 기준값은 실제 조명·노출에 맞춘 보정 전 초기값임.
- `extinguisher_aruco.py`를 YOLO 검사와 함께 호출하도록 연결함. 현재 검출된 소화기 영역 안에서 `DICT_4X4_1000` 마커를 읽고 ID·제조 정보·만료 상태를 화면과 로그에 표시함. ID 0·1·2의 제조 정보는 **더미 데이터**이며 실제 DB 조회나 ArUco 전용 토픽 발행은 아직 연결하지 않음.
- `shutter_obstacle.py`와 `inspect_shutter` 서비스를 추가·보완함. 압축 RGB, 정렬된 Depth, 각각의 CameraInfo, TF로 빨간 셔터 검사 구역을 찾고 RANSAC으로 바닥 평면을 추정한 뒤 바닥보다 높은 물체를 후보로 묶음. 선 조각 결합, 부분 구역 처리, 현재 영상으로 확인한 구역 추적, 바닥 근거 검증과 연속 판정을 추가함. **방화셔터 구역 위 물체 검출은 아직 완성되지 않음.**
- RGB·Depth 정렬을 같은 이름공간의 OAK-D 파라미터에서 비동기로 조회하도록 보완함. 정렬 설정·촬영 시각·크기·좌표계·CameraInfo·TF 근거가 부족하면 판정을 보류함. 기존 화면 클릭용 Depth 기능 대신 셔터 검사 입력으로 깊이를 사용함.
- RGB·Depth 시각 차이 기본 허용값을 **0.03초**로 줄이고, 차이가 가장 작은 옛 영상 쌍 대신 허용 범위 안의 **최신 Depth와 가장 가까운 RGB**를 선택하도록 변경함. 최신 MSI 코드에서는 지연되는 Depth와 짝을 찾기 위해 대기 RGB 목록을 90장까지 보관함. 촬영 시각을 수신 시각으로 덮어써 불일치를 숨기지 않음.
- 계산 시간이 길다는 이유만으로 선택한 Depth 결과를 바로 지우지 않도록 보완함. 다음 짝을 기다리는 동안 마지막 검사 화면을 유지하되 RGB·Depth 수신 또는 유효한 짝 선택이 기본 2초 동안 끊기면 미확인으로 전환함. 같은 Depth를 연속 확인 횟수에 중복해서 세지 않음.
- 셔터 화면·로그에 빨간 선 픽셀 수, 구역 후보/결합 조각, 바닥·유효 Depth 비율, 평면 기울기·근거, 후보 높이, 확인 프레임/시간을 표시함. 영상 발행 주기·촬영 시각 차이·상대 도착 지연·짝 선택 성공률 진단과 `test_shutter_timing.py`, `test_shutter_obstacle.py` 시험 코드를 추가함. 시험 코드 존재와 시험 통과는 구분하며 이번 정리에서는 테스트를 실행하지 않음.
- 마지막 동기화에서 MSI의 추가 수정도 반영함. 판지 바닥의 고정 Depth 오차를 장애물로 읽는 문제를 줄이기 위해 기본 최소 장애물 높이를 **20mm에서 70mm**로 변경함. 바닥 분류·평면 탐색 거리 상한은 15mm에서 52.5mm로 바뀜. 코드 주석과 MSI 실행 안내는 BR-T14의 10cm 이상 물체 요구를 근거로 들며, 실제 10cm 물체의 현장 검출률은 아직 검증하지 않았다고 명시함.
- 기존 `inspect_yolo` 서비스의 시작/중지 흐름에 압력·비상구·랙·ArUco를 연결함. 셔터 검사는 별도 서비스로 시작/중지하며 YOLO·기존 랙·셔터 검사 모드는 동시에 활성화하지 않음. 서비스 응답은 최종 정상/불량이 아니라 시작·중지 제어 성공 여부임.
- 현재 구현된 발행은 표시된 압축 영상과 **확정 비정상만 보내는 `inspect/result`**임. 압력·비상구·YOLO 랙 불량 및 셔터 확정 불량의 발행 경로가 코드에 연결되어 있으나, 모든 객체·정상·미확인·ArUco 정보를 관제에 일괄 전달하는 구조화 토픽은 후속 작업임. 메시지가 없다고 정상으로 판단하면 안 됨.
- 설계도에서 매니저 부분의 흐름을 현재 YOLO 객체 인식·설비별 후처리·ArUco와 향후 관제 전달 방향에 맞춰 정리함. 코드와 그림을 대조하여 구현된 기능과 향후 연결할 기능을 구분함.
- `rack_conditioner.py` 사용 여부와 남은 예전 코드를 재점검함. YOLO 랙 운용은 `rack_loading.py`를 사용하지만 기존 OpenCV 경로는 import, 기준 파일 처리, N/R 키, `inspect_rack` 서비스 분기에 남아 있음. 파일 전체가 미사용인 것은 아니며 이번 동기화에서 MSI 코드를 임의로 제거하지 않음.
- MSI의 최신 프로젝트 소스·모델·문서·시험 코드를 로컬 PC로 복사하고 내용 비교로 일치 여부를 확인함. MSI에 없는 로컬 옛 `depth_checker.py`, 편집기 설정, Python 캐시와 이전 빌드·설치·로그 산출물은 로컬 프로젝트에서 제거하고 외부 백업에 보존함. PC별 Git 정보와 빌드 산출물은 MSI에서 가져오지 않으며 로컬 재실행에는 새 빌드·source가 필요함.
- ChungBazi04의 오늘 추가된 사진 **10장**을 OmverYo의 `img`에도 같은 이름으로 복사하고, 두 작성자의 오늘 일지를 동일하게 작성함. 사용자 요청에 따라 **MSI는 읽기 전용으로 유지하고 사진·일지는 로컬 PC에만 작성함.**

## 시행착오

- 초반 셔터 화면에서 `rgb_depth_time_mismatch`가 발생해 구역·바닥 검사 전에 판정이 보류됨. 초기 사진은 허용값 0.100초였지만 현재 코드는 0.030초임. 허용값을 크게 늘려 해결했다고 기록하지 않고 시각이 맞는 최신 입력 쌍을 선택하는 방향으로 보완함.
- `zone_not_found`와 `zone_partial`이 반복됨. 바닥의 빨간 선이 조각으로 끊기거나 구역이 화면 밖으로 잘리는 조건을 확인하고 선 결합·부분 구역 처리·현재 영상에 근거한 추적을 보완함. 부분 구역에서 장애물이 없다는 이유만으로 전체 정상 판정을 내리지 않음.
- 19:54 사진에서는 상자가 있는 장면의 바닥과 물체 후보가 표시됐지만 `confirmation_pending` 상태임. 후보 박스가 보였다는 사실을 최종 검출 완료 또는 정확도 통과로 표현하지 않음.
- 20:42 사진의 `depth_alignment_unconfirmed`, 20:53 사진의 `floor_not_confirmed`처럼 정렬 확인과 바닥 근거 부족을 각각 구분함. 입력 영상 크기·프레임 이름이 같다는 것만으로 실제 픽셀 정렬을 보장할 수 없음.
- 21:14 사진에서는 RGB·Depth 시각 차이가 0.003초로 허용 0.030초 안이었지만, 바닥 확인은 70.0%, 유효 Depth는 94.9%, 연속 확인은 1/3프레임·0.00/0.50초였음. 시각 일치가 최종 정상/불량 확정을 뜻하지 않음.
- 물체를 치운 장면에서도 21:14 사진에 35mm·24mm 등의 높이 후보가 나타남. 센서 잡음, 바닥 평면, 선·경계 주변의 후보를 추가 점검해야 하며 현재 셔터 검출을 완성 상태로 기록하지 않음.
- MSI의 `docs/shutter_obstacle.md`에 기록된 21:29 녹화 재생 분석에서는 바닥 고정 오차와 가짜 장애물 문제를 확인하고 70mm 기준에서 가짜 후보 0장을 보고함. 이는 다른 작업에서 남긴 녹화 분석 기록으로, 이번 일지 정리에서 직접 재실행한 결과가 아님. 해당 녹화는 구역 잘림으로 여전히 미확인이며 실제 장애물 검출 성공이나 정상 판정 완료의 증거와 구분함.
- MSI 실행 안내에는 늦게 도착하는 Depth와 RGB 쌍 부족, 계산 뒤 결과 초기화에 대한 진단 기록이 있음. 대기 RGB 확대·최신 쌍 선택·신선도 확인 시점 분리·별도 단절 감시로 보완했지만 수정 후 실환경 개선 결과는 추가 확인이 필요함.
- 옛 압력계 각도 판독 함수·호환 파라미터와 사용하지 않는 Depth 모듈을 참조하는 시험 파일 등 일부 정리 대상이 남아 있음. MSI 원본 보존 요청에 따라 이번에는 삭제·수정하지 않고 후속 과제로 기록함.

## 강조하고 싶은 것 / 달성

- 객체 검출과 설비 상태 판독을 구분하고 매니저가 공통 영상·YOLO·ROS 실행을 담당하는 현재 구조를 확인함. 압력 정상 영역 안의 바늘 존재 판독, YOLO 랙 적재, 비상구 점등과 소화기 ArUco가 YOLO 검사 경로에 연결됨.
- 오늘의 셔터 달성 범위는 **구역·바닥·장애물 후보 계산과 원인 표시, 입력 시각·연속 확인 처리 보완**임. 최종 장애물 검출, 빈 구역의 안정적인 정상 판정, 관제 운영 검증은 미완료임.
- 이번 일지 정리는 MSI 코드·모델 클래스 읽기·파일 비교와 사용자 촬영 화면 확인을 근거로 함. 로봇 이동·카메라 설정 변경·추론·ROS 노드 실행·자동 테스트는 새로 수행하지 않았으며, 과거 테스트 통과 개수를 현재 수정본의 결과로 기재하지 않음.
- 로컬의 두 일지와 오늘 사진 10장은 동일하게 유지함. MSI에는 파일 쓰기·커밋·푸시를 하지 않음.
