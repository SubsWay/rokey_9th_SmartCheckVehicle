# RSSI 재점검 세 가지 문제 — 코드 수정 명세

이 문서는 **인계받은 개발자가 자기 통합 코드에서 같은 문제를 해결하도록 하는 구현 명세**다. 변경 배경만 읽고 끝나는 보고서가 아니라, 어느 함수에서 무엇을 제거·추가하고 어떤 순서와 조건으로 처리해야 하는지 정리했다. Git 반영, PC 구성, 빌드·실행 절차는 다루지 않는다.

## 1. 수정 대상과 완료 조건

| 문제 | 반드시 달라져야 하는 동작 |
| --- | --- |
| ① 미검출 원본이 사라짐 | 스캔은 했지만 AP가 안 보인 결과도 원본으로 보존. RSSI 평균에서는 제외하고 미검출 횟수에는 포함 |
| ② 좋은 값 한 번으로 정상 판단 / 무표본과 전부 미검출 혼동 | 검출 평균과 미검출 비율을 함께 판단. 결과 자체가 없으면 판정 불가, 충분히 시도했는데 전부 미검출이면 이상 |
| ③ 저장 실패 후에도 정상/완료 처리 | 저장 성공 전에는 판정 알림·작업 성공·다음 작업 배정을 확정하지 않음. 실패 결과는 보관하고 저장 재시도 |

여기서 `CLEARED`는 **정상 확인 → 해당 칸의 이상 의심 취소**, `REMAINS`는 **재점검해도 이상 지속**, `UNCONFIRMED`는 **판정 불가**다. ‘해제’는 데이터 삭제나 로봇 명령 취소를 의미하지 않는다.

## 2. 먼저 맞춰야 하는 데이터 의미

이 정의가 수신·집계·정밀측정·관제·DB에서 같아야 한다.

| 값 | 의미 | 주의 |
| --- | --- | --- |
| `detected` | 이번 스캔에서 대상 AP가 보였는가 | 스캔 자체가 실패해 결과가 안 온 것과 다름 |
| `rssi_dbm` | 검출되었을 때의 실제 RSSI | 미검출이면 값 사용 금지. 저장할 때 NULL |
| `n_detected` | 검출된 유효 스캔 수 | 정밀측정 액션의 기존 `n_samples`가 이 값 |
| `n_missed` | 미검출된 유효 스캔 수 | 미검출도 측정 시도 1회 |
| `n_total` | `n_detected + n_missed` | 전체 시도 수. 최소 표본 판단 기준 |
| `mean` / `rssi_mean` | 검출된 값만의 산술평균 | 미검출을 −100이나 0으로 평균에 섞지 않음 |
| `measurement_valid` | 이번 정지 측정이 판정에 사용 가능한가 | 표본 개수 외에 취소·위치·정지 조건도 함께 확인 |

**미측정**은 유효한 측정 시도 자료가 없는 칸이다. **미검출**은 측정 결과가 존재하고 AP가 없었다는 뜻이다. 둘을 동일한 ‘값 없음’ 상태로 합치면 안 된다.

## 3. 수정 ① — 미검출 원본이 사라지는 문제

### 3.1 기존 코드에서 잘못되던 지점

`ros_bridge.on_sample()`이 `detected=false`이면 바로 반환했다. 따라서 ROS 칸 집계에서는 미검출을 세더라도 웹/DB 원본에서는 그 시도가 사라졌다. DB도 RSSI 숫자를 필수로 요구해 ‘측정했지만 AP를 못 찾음’을 숫자 없이 담을 수 없었다.

### 3.2 수신 함수에서 바꿀 것

대상 파일: `ros2_ws/scv_app/ros_bridge.py` / `on_sample()`.

1. **미검출이라는 이유로 반환하는 조건을 제거한다.** 기존 도크 위 표본 제외 조건은 유지한다.
2. 저장 대기 자료에 기존 위치·시각·seq·작업 연결과 함께 `detected`를 추가한다.
3. 검출이면 실제 RSSI, 미검출이면 None을 넣는다.

핵심 변환은 다음과 같다. 나머지 기존 메타데이터를 제거하는 예시는 아니다.

```python
sample["detected"] = bool(msg.detected)
sample["rssi_dbm"] = int(msg.rssi_dbm) if msg.detected else None
```

수신 메시지에서 미검출 RSSI가 0으로 채워져 오더라도, 0을 측정값으로 저장하거나 평균에 넣으면 안 된다.

### 3.3 API의 원본 저장과 집계에서 바꿀 것

대상 파일: `ros2_ws/scv_app/server_page.py`.

| 함수/구간 | 수정 내용 |
| --- | --- |
| `on_samples()` | 원본 INSERT에 detected 포함. false면 RSSI NULL. 등록 AP·위치·중복 처리 등 기존 연결은 유지 |
| 같은 함수의 실시간 캐시 누적 | 원본은 검출/미검출 모두 저장하되, 숫자 히트맵 누적에는 검출 RSSI만 추가 |
| `live_cells()` | 서버 재시작 후 DB 원본에서 히트맵을 복구할 때도 검출만 count/sum/sumsq로 집계 |
| 원본 표본 조회 | 응답에 detected를 포함해 화면이 NULL을 ‘강한 신호’로 해석하지 않게 함 |
| 작업별 칸 통계 조회 | 전체 수, 검출 수, 미검출 수를 구분해 응답. 평균/중앙값은 검출 숫자만 사용 |

원본 저장 후 ‘히트맵 색을 계산할 수 있는가’를 따로 판단해야 한다. 히트맵 색이 없다는 이유로 원본 저장 자체를 생략하지 않는다. 기존 `(robot_id, run_id, seq)` 중복 방지 키는 유지한다.

### 3.4 DB 데이터 구조에서 바꿀 것

대상 정의: `ros2_ws/scv_db/sql/01_schema.sql`. 여기서는 적용 SQL 대신 필요한 구조를 명시한다.

| 대상 | 필요한 변경 |
| --- | --- |
| `net_samples.detected` | BOOLEAN NOT NULL, 기존 숫자 행과의 호환을 위한 기본값 true |
| `net_samples.rssi_dbm` | NULL 허용. detected=true면 숫자 필수, false면 NULL만 허용하도록 제약 |
| `grid_stats.n_detected` | nullable 정수, 값이 있으면 0 이상 |
| `grid_stats.n_missed` | nullable 정수, 값이 있으면 0 이상 |
| `grid_stats.n` | 새 결과에서 전체 시도 수. 두 횟수가 있으면 `n = n_detected + n_missed` |

기존 원본 숫자 행은 검출값으로 보존한다. 과거 −100을 전부 미검출로 바꾸지 않는다. 과거 칸 통계에는 미검출 횟수가 없을 수 있으므로 **모르는 횟수를 0으로 채워서 복원한 것처럼 만들지 않는다.** 이미 버린 원본은 이번 수정으로 복원되지 않는다.

### 3.5 화면에서 함께 바꾼 것

대상: `ros2_ws/scv_app/static/server/app.js`.

- 표본 점은 detected=false이면 회색과 ‘AP 미검출’로 표시한다.
- RSSI NULL/undefined/유효 숫자 아님을 신호 색 함수에서 처리한다. NULL이 숫자 0처럼 해석돼 강한 신호로 보이면 안 된다.
- 작업 상세 지도의 대표값을 검출 평균으로 연결한다.

**이 문제의 완료 조건:** 검출 1회·미검출 3회를 받으면 원본 4건이 존재하고, 숫자 평균은 검출 1건으로만 계산되며, 미검출 수는 3이어야 한다.

## 4. 수정 ② — 잘못된 정상 판단과 무표본 혼동

### 4.1 기존 코드에서 잘못되던 지점

기존 `precise_server`는 검출된 값만 리스트에 넣고 검출 수·중앙값을 반환했다. 관제는 좋은 값 한 개로도 정상 판단할 수 있었다. 메시지 0건과 전부 미검출도 둘 다 빈 리스트가 되어 구분하지 못했다.

### 4.2 정밀측정 결과에 추가할 정보

대상:

- `ros2_ws/src/scv_msgs/action/PreciseMeasure.action`
- `ros2_ws/src/scv_msgs/action/ExecuteTask.action`

두 결과 계약에 다음 정보를 같은 의미로 추가한다.

| 필드 | 타입 | 채우는 값 |
| --- | --- | --- |
| `rssi_mean` | float32 | 검출 산술평균. 검출 0개면 사용하지 않는 값 |
| `n_total` | uint16 | 검출 + 미검출 시도 수 |
| `n_missed` | uint16 | 미검출 수 |
| `duration_s` | float32 | 실제 정밀측정 경과 시간 |
| `measurement_valid` | bool | 결과를 판단에 사용할 수 있는지 |
| `measurement_reason` | string | 취소·표본 부족·조건 실패 등의 사유 |

기존 `n_samples`는 **검출 수**로 유지한다. 기존 중앙값/IQR도 진단용으로 남긴다. 필드 기본값이 0이어도 그것만으로 ‘검출된 좋은 신호 0 dBm’이라고 판단하지 않는다.

`mission_executor`가 정밀측정 결과를 받을 때 이 필드들을 ExecuteTask 결과에 그대로 전달해야 한다. 관제가 사람용 reason 문자열에서 median/n을 추출하던 우회 처리는 제거한다. 새 횟수와 유효성이 없는 결과를 추측해 정상으로 처리하지 않는다.

### 4.3 같은 판정 함수를 1차와 재점검에서 사용

대상:

- `scv_survey/heatmap.py`의 `CellStats.mean`, `cell_status()`, `rf_status()`.
- 관제 `inspection_manager.remeasure_state()`.

기준은 **검출 평균 −72 dBm 미만 또는 미검출 비율 50% 이상**, 전체 최소 3회다. 중앙값은 이번 판정 기준으로 사용하지 않는다.

아래는 현재 판단을 독립적으로 재현한 참조 함수다. 함수 이름은 달라도 입력과 결과 의미는 같아야 한다.

```python
import math

def judge_remeasurement(mean, detected, missed, valid):
    total = detected + missed
    if not valid or detected < 0 or missed < 0 or total < 3:
        return None  # 판정 불가: 정상/이상으로 확정하지 않음

    if detected > 0:
        if mean is None or not math.isfinite(mean) or not -127 <= mean <= 0:
            return None

    if detected == 0 or missed / total >= 0.5:
        return "miss"       # 충분히 시도했으나 대부분/전부 미검출
    if mean < -72.0:
        return "shadow"     # 약한 신호
    return "normal"
```

1차 분류도 같은 평균·미검출 조건을 사용하고, 후보로 선정하기 전에 전체 최소 표본을 검사한다. 표본이 적어 후보에서 제외된 칸을 ‘미측정’으로 바꿔 취급하지 않는다.

관제 `remeasure_state()`는 위 판정 전에 다음도 검사한다.

- `measurement_valid=true`.
- `n_total = n_samples + n_missed`.
- 실제 측정 시간 10~16초. 요청은 10~15초이며, 결과의 16초 상한은 종료 루프 지연 허용분이다.
- 액션 자체가 성공한 결과인지 확인. abort/cancel을 결과 객체가 있다는 이유만으로 성공 처리하지 않음.

예를 들어 −60 dBm 1회·미검출 29회는 평균 −60이지만 미검출 96.7%이므로 `miss`다. ‘정상 확인 → 이상 의심 취소’로 처리하면 안 된다.

### 4.4 표본 수집기에서 바꿀 것

대상: `scv_survey/precise_server.py`.

1. 요청을 받으면 이번 측정의 시작 시각과 수집 창을 만든다. 기본 요청 시간은 15초, 허용 요청은 10~15초다.
2. 검출은 RSSI 리스트에 넣고 미검출은 별도 횟수를 증가시킨다.
3. 모은 검출값으로 평균/중앙값/IQR을 계산하고, 전체·검출·미검출 수를 모두 반환한다.
4. 충분한 시도에서 전부 미검출이면 유효한 측정 결과가 될 수 있다. 무표본/전체 3개 미만이면 유효하지 않다.
5. 동시 측정 요청은 거절하고, 종료·취소·예외 시 수집 상태/잠금을 정리한다.

현재 구현에서 제외하는 표본 조건:

| 제외 조건 | 이유 |
| --- | --- |
| robot_id가 측정 중인 로봇과 다름 | 다른 로봇 자료 혼입 방지 |
| 이미 받은 같은 측정 시각 | NetRaw에 seq가 없어 시각으로 중복 제거 |
| 측정 시작 전 또는 요청 시간 창 뒤 | 이전 캐시/다른 구간 표본 제외 |
| 현재 ROS 시각보다 미래 또는 수신 시점에 2초보다 오래됨 | 잘못된 시각/과거 표본 배제 |
| detected=true인데 RSSI가 −127~0 범위 밖 | 잘못된 측정값 제외 |

수집 시간 제한은 단조 시계로 관리하고 원본 시각은 ROS 측정 시각으로 확인한다. 안 온 메시지를 미검출 1회로 만들어 세지 않는다. 현재 최소 3회 검사는 측정 시간 동안의 꾸준한 수신 빈도를 보장하는 수집률 검사는 아니다.

### 4.5 이동 측에서 결과 유효성을 만드는 조건

대상: `ros2_ws/src/scv_nav/scripts/mission_executor.py`의 `on_odom()`, `measurement_guard()`, `measure()`, 결과 전달과 `call_action()`.

- 기본 30초 요청을 15초로 바꾼다. 설정 허용 범위는 10~15초다.
- 기존 목표점까지 이동한 뒤 정지 명령을 내리고, 1초 정지 확인 후 정밀측정을 요청한다.
- 측정 중 조건을 반복 검사하고 결과를 받은 뒤 다시 확인한다.

| 조건 | 이번 구현 기준 |
| --- | --- |
| 목표 식별 | `target_ref=cell:ix,iy` 형식 |
| 셀 | 지도 원점·셀 크기로 계산한 현재 셀이 목표 셀과 같음 |
| 위치 품질 | AMCL 위치 존재, 위치 표준편차 ≤ 기본 0.15 m |
| 지도 | 지도 원점을 가진 static_map이 존재 |
| 위치 이탈 | 시작 위치 대비 ≤0.05 m, 방향 차이 ≤0.10 rad |
| odom | 수신 나이 ≤1초, 선속도 ≤0.02 m/s, 각속도 ≤0.05 rad/s |
| 배터리 | 기존 귀환 기준 20%보다 높음 |

조건 실패나 취소이면 정밀측정을 중단하고 판정 불가로 전달한다. 정상으로 취급하지 않는다. 기존 셀 중앙점은 유지했으며, 새 이동 경로나 셀 내부 이동 측정을 만든 변경은 아니다.

### 4.6 remeasurement.py를 새로 만든 이유

`ros2_ws/src/scv_survey/scv_survey/remeasurement.py`는 이번 수정에서 새로 추가했다. 기존 통합 코드에서 받아온 파일이 아니다.

- `classify()`는 유효성·최소 표본을 검사한 뒤 기존 heatmap의 공유 분류 함수를 호출한다.
- `MeasurementWindow`는 위 시간 창·로봇·중복 조건과 검출/미검출 수집을 담당한다.
- 실제 사용처는 `precise_server`와 `inspection_manager`다.

인계받은 쪽에서 같은 이름의 파일을 반드시 새로 만들 필요는 없다. **동일한 검사와 판정을 공유하고 두 경로가 다른 규칙을 쓰지 않도록 구현하는 것**이 목적이다. 기존 재점검 기능 전체를 이 파일에서 새로 만든 것이 아니다.

**이 문제의 완료 조건:** 충분한 전부 미검출은 이상, 무표본/부족/위치·정지 실패는 판정 불가, 정상은 평균과 미검출 조건을 모두 통과한 경우에만 가능해야 한다.

## 5. 수정 ③ — 저장 전 성공/완료 처리

### 5.1 기존 코드에서 잘못되던 지점

기존 `inspection_manager.on_task_result()`는 재점검 결과를 저장하기 전에 작업을 성공으로 닫았다. `apply_remeasure()`도 저장 함수의 False를 확인하지 않거나 예외 로그 뒤 판정 알림을 발행할 수 있었다. 결과적으로 화면/작업은 정상인데 DB는 이전 값을 가진 상태가 가능했다.

### 5.2 결과 처리 순서를 바꿀 것

대상: `inspection_manager.py`의 `on_task_result()`, `apply_remeasure()`.

```text
재점검 액션 결과 수신
→ 액션 성공·측정 유효성 검사
→ 평균/미검출로 판정
→ 칸 저장 시도
   ├─ 성공: 확정 회피 집합 갱신 → 판정 알림 → 작업 성공 종료
   └─ 실패: 결과 보관 → 성공 종료하지 않음 → 저장 재시도
```

반드시 지켜야 할 조건:

1. `apply_remeasure()`가 저장 성공 여부를 bool로 반환하게 한다.
2. 저장 False 또는 DB RuntimeError/파일 OSError이면 False로 끝낸다. CLEARED/REMAINS를 발행하지 않는다.
3. 호출부는 False이면 `finish_task(ok=True)`를 실행하지 않는다.
4. 측정 결과 자체가 판정 불가이면 UNCONFIRMED/실패로 처리한다. 기존 칸을 무표본 결과로 덮지 않는다.
5. 정상/이상 판정이 가능하고 저장에 성공한 뒤에만 알림과 작업 완료를 확정한다.

작업 완료를 먼저 호출한 뒤 DB 실패 시 되돌리려는 순서가 아니라 **저장을 먼저 확인하는 순서**여야 한다.

### 5.3 저장 재시도에 필요한 상태

현재 추가한 메모리 구조:

| 상태/함수 | 역할 |
| --- | --- |
| `pending_remeasure_results[task_id] = (robot_id, result)` | 다시 측정하지 않고 같은 수집 결과의 저장을 재시도하기 위해 보관 |
| `retry_remeasure_results()` | 취소/종료된 작업은 제외하고 저장 재시도. 성공하면 보류 결과 제거 후 작업 성공 종료 |
| 기존 dispatch 주기 | 0.5초마다 저장 보류를 먼저 확인. 남아 있으면 다음 작업 배정 보류 |
| 회차 시작 초기화 | 이전 회차의 보류 결과가 새 회차에 섞이지 않게 비움 |

저장 재시도 때문에 정밀측정을 다시 실행하거나 표본을 중복 합산하지 않는다. DB upsert는 같은 회차·AP·칸의 결과 갱신이어야 한다. 다음 작업 배정 보류는 이미 이동 중인 다른 작업에 정지 명령을 내리는 기능과는 다르다.

이 큐는 메모리이며 프로세스 재시작 시 복구되는 디스크 버퍼는 아니다. 재시작 복구까지 해결했다고 인계하지 않는다.

### 5.4 File/DB 저장 함수도 같이 바꿀 것

대상: `ros2_ws/src/scv_survey/scv_survey/cellmap_store.py`.

| 구간 | 실제 변경 |
| --- | --- |
| `CellRow` | 기존 상태/중앙값/전체 수/신뢰도에 mean, n_detected, n_missed 추가 |
| `rows_from_stats()` | 전체·검출·미검출 수와 검출 평균을 만들고 전체0이면 통계 행 생성하지 않음 |
| FileStore 읽기/갱신 | 요청 회차가 다른 문서는 제외 |
| File/DB의 `update_cell()` | 상태·전체 수·검출/미검출 수·평균·중앙값을 새 결과로 함께 갱신 |
| 횟수 검사 | `전체 = 검출 + 미검출` 불일치이면 잘못된 요약으로 취급 |
| 신뢰도 | 두 저장소 모두 전체 ≥3이면 ok, 미만이면 low. 0개를 DB에서 무조건 ok로 저장하던 처리 제거 |
| 이전 통계 | 새 요약에 없는 var/min/max를 NULL로 비움. 이전 측정 통계와 섞지 않음 |
| DB 추가 표시 | 갱신 시 기존 interpolated와 baseline_delta 표시도 초기화 |
| 저장 대상 없음 | DB grid_cells에 목표 셀이 없으면 False. 성공한 것처럼 반환하지 않음 |

재측정 후 mean은 새 측정 평균이어야 한다. median/n만 바꾸고 mean을 1차 측정 값으로 남기면 화면과 판정이 다시 어긋난다.

### 5.5 회피 마스크에 반영할 것

대상: `inspection_manager.apply_remeasure()`와 `begin_facility_phase()`.

- 저장된 결과가 정상이라면 `confirmed_cells`에서 해당 셀을 제외한다.
- 저장된 결과가 이상 지속이면 해당 셀을 집합에 추가한다.
- 설비 단계의 마스크는 이번 집합에 있는 셀만 칸 저장소에서 골라 만든다.
- 기존 confidence와 Dock 보호 반경(기본 0.6 m) 예외는 유지한다.
- 무표본·저장 실패·미재점검 후보를 이번 재점검에서 확정된 이상처럼 회피 집합에 넣지 않는다.

이 집합도 현재 메모리 상태다. DB 후보 이력의 CONFIRMED/finding 저장까지 완료하는 기능과 같지 않다.

**이 문제의 완료 조건:** 저장 함수가 False/예외를 내면 성공 알림도 작업 성공도 없고, 같은 결과의 저장이 복구된 후에만 성공 처리되어야 한다.

## 6. 세 문제와 연결되어 함께 바꾼 규칙

인계받은 쪽에서 기존 설정을 그대로 두면 결과가 달라질 수 있어 구분한다.

| 위치 | 이번 변경 |
| --- | --- |
| `inspection_manager.queue_cell_candidates()` | 1차 후보도 전체 최소3을 충족한 칸에서 선정 |
| 같은 관제의 후보 수 | 기본 max_remeasure_per_robot를 5에서 0(전체)으로 변경. 양수 설정을 따로 주면 그 제한은 유지 |
| `manager_core.remeasure_targets()` | 약한 신호는 평균이 낮은 순으로 정렬. 최소 표본 필터를 적용하되 표본 부족 칸을 미측정으로 바꾸지 않음 |
| `network_map_engine.py` | 미리보기 색과 칸 숫자도 평균 사용, 기본 마스크 최소3 |
| `cell_map_writer.py` | 표본 부족 안내를 최소3으로 맞춤 |
| `02_seed.sql` 및 기존 설정 이전 | 새 기본 시간15, 기존 정확히30인 설정을15로 이전. 다른 값을 임의로 덮지 않음 |

현재 미검출 비율은 0.5, 최소 표본은 코드 기본3이다. DB 설정을 바꾸면 모든 ROS 노드의 값이 자동으로 바뀌는 기능까지 만든 것은 아니다. 서로 다른 사용자 설정을 쓰고 있다면 같은 회차의 기준을 일치시켜야 한다.

미측정 재방문 옵션과 과거 실기 기록은 기존에 있다. 현재 include_unmeasured 기본 false이며, 별도 미측정 칸 채우기(N-8)는 이번 수정 대상이 아니다.

## 7. 인계받은 구현의 확인 기준

명령이 아니라 **입력과 기대 동작**을 기준으로 확인한다. 실제 판정 가능 조건을 만족한 결과를 넣는 경우와 의도적으로 무효로 만드는 경우를 나눈다.

| 확인 입력/상황 | 반드시 나와야 하는 결과 |
| --- | --- |
| 원본 검출1·미검출3 | 원본4건, 미검출3, 숫자 평균에는 검출1건만 포함 |
| 같은 원본 묶음 재전달 | 기존 고유 키 기준 원본 중복 증가 없음 |
| 검출 −90/−65/−65 | 평균 −73.33으로 약한 신호. 중앙값 −65로 정상 판단 금지 |
| 평균 정확히 −72, 미검출0 | 평균 조건상 정상 |
| 검출3·미검출3 | 미검출 비율50%로 이상 |
| 검출1·미검출29, 검출값−60 | 평균이 좋아도 미검출96.7%이므로 이상 지속 |
| 검출0·미검출15 | 충분한 미검출 결과. 이상 지속, 저장 평균은 NULL |
| 검출0·미검출0 | 수집 결과 없음. 판정 불가, 기존 칸 유지 |
| 전체1~2개 | 표본 부족. 정상/이상 확정 금지 |
| 측정 중 이동/칸 이탈/위치 불확실/취소 | 판정 불가. 짧게 모은 좋은 값으로 정상 취소하지 않음 |
| 이전 시각·중복·다른 로봇 표본 | 이번 정밀측정 집계에서 제외 |
| 저장 False | 판정 알림·작업 성공 없이 보류 결과 존재 |
| 저장 예외 후 복구 | 원래 측정 결과로 저장 재시도, 성공 후 알림/작업 완료 |
| 0표본 저장 함수 단독 확인 | File/DB 모두 low. DB만 ok가 되면 안 됨 |
| 재점검으로 값 변경 | mean과 횟수도 새 결과, 이전 var/min/max 잔존 없음 |
| 저장 성공한 이상 셀/정상 셀 | 이상만 확정 회피 집합, 정상은 제외. Dock 보호 예외는 별도 유지 |

이번에 추가·수정한 시험은 `test_remeasurement.py`, `test_precise_server.py`, `test_cellmap_store.py`, `test_remeasure_result.py`, `test_bundle_logic.py`, `test_measurement_guard.py`, `test_rssi_storage.py`에 있다. 기존 mock_execute_task_server도 새 필드를 채우도록 맞췄다. 테스트 더블도 검출 수만 채우면 새 판정에서는 유효한 결과가 아니다.

## 8. 이번 수정의 범위 경계

이 명세는 세 결함과 연결된 판정·수집·저장 수정을 재현하기 위한 것이다. 다음을 해결한 것으로 확장해서 해석하지 않는다.

- 원본의 실제 run_id 연결·디스크 재전송·통신 누락 복구 전체.
- `precise_measures / candidates / findings`의 전체 DB 이력 연결. 현재 REMAINS 알림과 DB CONFIRMED 완료는 별개.
- 보류 결과와 회피 집합의 프로세스 재시작 복구.
- 최초 칸 맵 확정 타임아웃/읽기 실패 처리, 별도 미측정 채우기, 안전 대체점·셀 내부 이동 측정, 수집률 검사.

기존 DB 상태 매핑은 내부 normal→DB normal, shadow→coverage_suspect, miss→unknown이다. unknown 문자열 하나로 무표본과 미검출을 다시 합치지 말고 횟수와 결과 유효성을 함께 본다. 이번 정상 확인은 ‘후보 의심을 취소’하는 것이고, 별도의 공간 전체 커버리지나 통신 품질을 보증하는 것은 아니다.
