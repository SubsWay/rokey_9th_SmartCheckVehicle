# SCV 비즈니스 요구사항 (제출용 초안 v0.1)

> 이 저장소 문서가 원본이다 (10/11 PM 결정). 노션 「SCV 설계」는 10/10 까지의 예전 판이다.

2026-10-10 · 작성 도윤 (PM) · 출처: 팀 노션 「SCV 설계」 8장 (10/10 기준). 번호는 노션과 같습니다.

시나리오 (10/12 PM 결정 — 10/11 의 「A → B → A · 역할 분리 · 번갈아 구동」을 대신한다): 두 로봇이 동시에 주행한다. 구역을 섹터 2개로 나눠 로봇 A(`/robot4`)·로봇 B(`/robot3`)가 하나씩 맡고 같은 일을 한다 — ① Undock → 자기 섹터 RSSI 측정 → Dock ② 재측정이 필요한 칸(음영·미검출)이 있으면 그 칸으로 가 정지 30초 재측정 → Dock (없으면 건너뜀) ③ 물리 인프라 점검 → Dock. ③ 에서는 재측정 뒤에도 음영·미검출로 남은 칸을 회피 구역으로 피해 간다. 로봇마다 최대 3바퀴(재측정이 없으면 2바퀴). 측정·판정 노드는 두 로봇 쪽에 모두 올린다. 두 Dock 은 각자 섹터 안에 떨어져 있어(약 3.6 m) 두 로봇이 동시에 출발하고 각자 Dock 으로 돌아온다. 음영 때문에 갈 수 없는 설비는 관제가 예외로 처리한다. 랙 적재물 돌출 점검을 더한다 (OpenCV, BR-T16). (BR-T01·T06·T07·T08, UC-01·02·06·08 을 고침)

## 1. 목표

산업 자동화 시설의 **물리 인프라(소방·안전·고정 설비)와 통신 인프라(AMR 운행 경로의 Wi-Fi)를 같은 순찰에서 사람 없이 반복 점검**해 위치 기반 기록과 지도로 유지하고, 이상 후보는 재검증해 확정한다. 법정 점검 사이의 설비 점검 공백을 메우고, 무선 끊김으로 인한 자동화 설비 정지를 미리 막을 근거를 준다. 전문 RF 설계·법정 점검을 대체하지 않고 그 사이를 보완한다.

- 이름: SCV (Smart Check Vehicle). 대상: 산업 자동화 시설(대표: 스마트 물류창고). 검증: 강의장 축소 테스트베드.

## 4. 기술·운영 요구사항 (BR-T)

| BR-T01 | 측정 커버리지 | 등록 구역 100 % 를 측정 간격 2 m 이하로 (시연 시간 목표는 따로 두지 않는다 — 풀사이클 시험에서 잰다, 10/12 회의) |

| BR-T04 | 지도·신뢰도·보고 | 0.5 m 칸별 중앙값 · 칸 상태(미측정 · 미검출 · 음영 · 정상) · −72 dBm 미만 음영 100 % 표시 · 순찰 종료 후 보고서 |
| BR-T05 | 기준선 대비 변화 | 여러 회차의 정상 분포에서 벗어난 칸 자동 표시 |
| BR-T06 | 이상 후보 재검증 | RSSI 저하·기준선 이탈·설비 미검출은 '후보'로만 등록 → 음영·미검출·미측정 칸은 그 섹터를 맡은 로봇이 재방문해 정지 정밀 측정, 설비 후보는 점검한 로봇이 자세를 바꿔 다시 관측한 뒤 최종 판정 · **재검증 없이 '이상' 확정 0건** |
| BR-T07 | 음영 회피 | 재측정 뒤에도 기준 미달인 칸을 회피 구역으로 표시해 두 로봇의 설비 점검 경로에서 제외(표시 후 5초 이내 재계획) · 측정·재측정 때는 회피하지 않음(재측정은 그 칸 안에서) · 남은 칸은 관제 알림으로 사람이 확인 · 측정값 유실 0건 |
| BR-T08 | 협업·병합·인계 | 두 로봇이 섹터를 나눠 동시에 측정하고 한 지도(히트맵)로 합쳐 두 로봇의 점검 경로에 반영 · 한 대 이탈 후 60초 이내 남은 작업 재배정, 누락 0 (추가 기능 — 풀사이클이 돈 뒤에 넣는다 (10/11 PM 결정)) |

## 5. 비즈니스 규칙 (BR-R)

| ID | 규칙 · 제약 |
| --- | --- |
| BR-R01 | SCV 는 측정·점검·기록까지만 한다. 조치는 담당자가 하고, 로봇은 다음 순찰에서 결과를 다시 확인한다 |
| BR-R02 | 후보·미확인·보간값은 확정값이나 정상으로 처리하지 않는다 |
| BR-R03 | 사람과 지게차가 항상 먼저다 |
| BR-R04 | 측정 구역·설비 등록·기준·순찰 일정은 관리자만 바꾼다 |
| BR-R05 | 영상은 점검 목적으로만, 얼굴 저장 최소화 · 측정 데이터는 시설 내부에만 |
| BR-R06 | 전문 RF 설계·법정 점검을 대체하지 않는 보조 모니터링으로 운영한다 |
| BR-R07 | 축소 테스트베드 결과를 실제 창고 재현이라 주장하지 않는다 · 휴대폰 핫스팟으로 만든 음영을 실제 설비 AP 음영과 같다고 주장하지 않는다 |

## 7. 성과 지표 · 유스케이스

| 지표 | 도입 전 | 목표 |
| --- | --- | --- |
| 네트워크 지도 갱신 주기 | 문제가 생기면 외주 측정 | 주 1회 이상 (순찰마다) |
| 음영 문제를 아는 시점 | 로봇·단말이 멈춘 뒤 | 순찰 측정 시 (장애 전) |
| 측정 조건 일관성 | 측정자마다 다름 | 같은 경로·높이·속도 |
| 1회 측정으로 확정한 이상 | 오탐 구분 없음 | 0건 (모두 재검증 후 확정) |
| [물리] 소방 설비 확인 빈도 | 연 1–2회 + 수시 | 매일 (순찰 1회 이상) |

- UC-01 정기 순찰: 관제에서 시작 → 섹터마다 작업 배정 → 두 로봇이 동시에 자기 섹터를 측정 → 히트맵 → 재측정(필요할 때) → 남은 음영을 피해 설비 점검
- UC-02 음영 후보 재측정: 1차 측정의 음영·미검출·미측정 칸 → 그 섹터의 로봇이 Dock 에서 다시 출발해 그 칸 안에서 정지 측정 → 사라지면 해제, 남으면 회피 구역
- UC-03 배치 변경 후 재측정 → 기준선 대비 변화 구역
- UC-04 순찰 보고서: 음영·커버리지 저하 의심 구역 → IT 담당 확인
- UC-05 관제에서 비상정지 · 로봇 이탈 감지와 경보 (남은 작업 인계·재배정은 추가 기능 — 풀사이클이 돈 뒤에 넣는다 (10/11 PM 결정))
- UC-06 [물리] 소화기 미검출 → 점검한 로봇이 자세를 바꿔 재확인(최대 3회) → 판정 또는 미확인 / 압력 이상 알림
- UC-07 [물리] 셔터 적치·유도등 소등·랙 적재물 돌출 → 알림 → 다음 순찰 해소 확인
- UC-08 [통신] 1차 측정의 음영 칸 → 재측정 → 그래도 남은 칸은 회피 구역이 되어 점검 때 피해 감 · 관제에 알림을 띄워 사람이 확인 · 그 때문에 못 가는 설비는 관제가 예외 처리(미확인)

인수 기준: 검증 시나리오에서 팀이 고른 핵심 BR-C·BR-T 목표를 모두 충족하고, 해결되지 않은 안전 문제가 없을 때 인수한다. 시험과의 대응은 `docs/TEST_PLAN.md`.
